# 01. 기획 — KBO 유리몸 트래커

## 한 줄 정의
2021–2026 시즌 KBO 선수들의 부상 이력을 수집해, 선수별 SVG 신체 지도 위에 부상 부위를 빈도/결장일수에 따라 노랑·주황·빨강으로 표시하고, "누가 가장 자주·오래·중요한 순간에 빠졌는가"를 팀/리그 단위로 비교하는 대시보드.

## 왜 만드는가 (문제 의식)
- 타율·ERA·WAR 같은 성과 지표는 "뛰었을 때 얼마나 잘했나"만 말한다.
- "얼마나 자주, 얼마나 오래, 언제 빠졌나"는 흩어진 뉴스 기사에만 존재하고 누적해서 보여주는 곳이 없다.
- 특히 **가을야구 직전 이탈**, **복귀-재부상 반복** 패턴은 팬 입장에서 가장 체감되는데 정량화된 적이 없다.

## 핵심 지표: 유리몸 지수 (Glass Body Index, GBI)
세 가지를 합산한다. 가중치는 설정값으로 빼서 나중에 조정.

| 요소 | 정의 | 기본 가중치 |
|---|---|---|
| 빈도 (F) | 6시즌(2021–2026) 동안 발생한 부상 건수 | 1.0 |
| 결장 (D) | 부상으로 빠진 누적 일수 ÷ 30 | 1.0 |
| 타이밍 (T) | 9월 1일 이후 또는 포스트시즌 중 발생한 부상 건수 | 1.5 |
| 재발 (R) | 같은 부위에 2회 이상 발생한 횟수 | 1.2 |

`GBI = F + D + 1.5T + 1.2R`

부위별 색상 (선수 1명, 6년 누적, 부위 1곳 기준):

| 색 | 조건 (둘 중 하나라도 충족) |
|---|---|
| 노랑 | 1–2회 또는 결장 1–30일 |
| 주황 | 3–4회 또는 결장 31–90일 |
| 빨강 | 5회 이상 또는 결장 91일 이상 |

## 솔직한 평가 (만들기 전에 알아야 할 것)

**좋은 점**
- 시각화 포맷(신체 히트맵)이 직관적이고, 기존에 없는 관점이라 공유가치가 있다.
- 10개 구단 × 최대 6년이라 데이터 볼륨이 작아 Supabase 무료 플랜(500 MB)으로 충분하다.

**가장 어려운 부분은 UI가 아니라 데이터다**
1. KBO는 MLB의 IL(부상자 명단)처럼 공식 부상 리스트를 공개하지 않는다. 뉴스만으로는 "언제 복귀했는지"가 자주 누락된다.
2. 그래서 **두 소스를 결합**해야 정확해진다.
   - KBO 공식 **1군 엔트리 등록/말소** 기록 → "언제부터 언제까지 빠졌나" (날짜 정확, 부위 없음)
   - 뉴스 검색 → "어디를 다쳤나" (부위 있음, 날짜 부정확)
   - 말소 사유는 부상 외에도 부진·휴식·징계가 있으므로 뉴스로 교차검증 필요.
3. 뉴스 본문 파싱은 키워드 사전으로 시작하되, 정확도가 부족하면 LLM 추출로 교체할 수 있게 파이프라인을 분리한다.
4. 네이버 뉴스 페이지 직접 스크래핑은 약관 문제가 있다. **네이버 검색 Open API(뉴스)** 를 쓰면 무료(일 25,000회)이고 합법적이다. 단, 쿼리당 최대 1,000건이라 선수×연도로 쪼개서 조회한다.

**표현 주의**
- 실명 선수를 "최악의 유리몸"으로 랭킹하는 것은 개인 프로젝트에선 문제없지만 공개 배포 시에는 "부상 이탈 지수" 같은 중립 표현을 기본으로 두고, "유리몸" 같은 표현은 토글/별명 수준으로 두는 것을 권장.

## 범위
### MVP (1차)
- 삼성 라이온즈 1개 구단, 2021–2026 시즌 전체 수집으로 파이프라인 검증
- 수집 품질과 결과가 만족스러우면 타 구단으로 점진 확장
- 선수 상세: SVG 신체 지도 + 부상 타임라인
- 팀 랭킹: GBI 순 테이블

### 2차
- 10개 구단 × 6시즌 전체
- 리그 전체 랭킹, 부위별 리그 통계 (가장 많이 다치는 부위)
- 엔트리 말소 데이터 결합으로 결장일수 정밀화

### 3차 (선택)
- LLM 기반 기사 추출로 정확도 개선
- 시즌 타임라인 애니메이션, 포스트시즌 이탈 하이라이트

## 성공 기준
- 수집한 부상 건 중 수동 샘플 50건 검수 시 부위 정확도 85% 이상
- 선수 페이지 로딩 1초 이내 (정적 JSON 기반)
